## C04｜部署架构：统一入口、国内外节点与 CDN 取舍

日期：2026-10-16。来源：项目负责人和助手的部署讨论。状态：方向已明确，具体拓扑与实施参数待评审。关联 #2 概念阶段。

### 已明确的约束

- 使用 daedalOS 二开；服务器和访客均分布于国内外。
- 对外主入口保持 **hyc.ac**，正常使用不要求访客记住或切换其他域名。
- 当前先保留根域名指向 GitHub Pages 的解析，顾及其他项目。讨论期间核验到四个 GitHub Pages A 记录，Pages 绑定 hyc.ac 且 HTTPS 已启用；这是当时的观察记录，不是持续监控结果。
- 前端先沿用 GitHub Pages；优先设计独立内容服务的多节点能力。
- GitHub Pages 已有 CDN，额外 CDN 作为待测速、待验证的候选，不设为当前部署前提。讨论中没有修改 DNS、Pages 配置或服务器。
- 负责人拥有其他域名，可作为后续后台方案的资源；具体 API/媒体域名及启用方式尚未确定。

### 初步分层方案

| 部分 | 方向 | 仍需确定 |
| --- | --- | --- |
| 桌面前端 | hyc.ac → GitHub Pages；兼容已有项目路径 | 构建发布、内容直链、资源路径与 SEO |
| 内容 API | 独立服务，支持国内外节点和受控流量分配 | 节点角色、负载均衡、健康检查、故障切换、身份配置 |
| 数据与媒体 | API 节点使用一致的内容和授权数据来源 | 数据库、媒体存储、会话、复制方式与备份恢复 |
| 额外 CDN | 测量现状后再决定是否采用厂商服务 | 实际区域收益、缓存规则、回源、HTTPS、刷新与故障行为 |

多个 API 实例不能各自以独立本地 JSON/上传目录充当权威数据源。跨区域单写、多读、复制和写入切换需要明确方案；不默认采用复杂的双区域同时写入。R13 内容服务是研究夹具，不是生产部署实现。

浏览器可以在保持地址栏 hyc.ac 的同时调用其他接口地址；身份与内容 API 必须正确处理跨域访问、会话、CSRF 和 visitor/admin 权限。语言选择与服务器区域调度分别处理，不以界面语言推断地理位置。

### 已接受的现阶段限制

保留根域名当前解析意味着首页首次访问仍依赖 GitHub Pages。后端多节点不能替代这个入口的可用性，也不等于数据库和整个系统已经高可用。

如果未来需要 hyc.ac 的前端也经过自有 CDN/多源入口，对外域名仍可保留，但公开 DNS 解析或流量入口将发生调整；必须另行评审现有项目路径、回源、域名校验、证书签发/续期和回退方案。当前没有批准这种现网切换。

### 本议题需要产出的决定

1. 域名与路径清单：hyc.ac 的既有项目、前端资源、API、媒体和管理请求如何组织。
2. 分阶段拓扑：初期节点数、国内外职责，以及扩容/容灾的触发条件。
3. 可用性目标：允许的中断时间、数据恢复范围、预算和跨区延迟容忍度。
4. 数据与会话方案：权威数据源、复制、发布一致性、下架/缓存失效、备份和恢复。
5. CI/CD 与回退：同一构建产物、发布版本、配置管理、健康检查、日志监控及数据库迁移兼容。
6. CDN 评估：国内外真实访问测量、冷/热缓存、登录与管理写入、直链刷新；以实际收益决定是否加层，不预先承诺访问提速。

概念阶段完成条件：上述决定形成明确方案、验收要求和待办清单，再交 #3 计划阶段拆分；部署实施与故障演练交 #4/#5，持续维护交 #6。本 Issue 的创建不表示已经部署多节点或配置负载均衡。
