# Messenger：站长联系能力核验

2026-10-17 · 源码核验。**当前状态：负责人已要求暂缓，后续由 [Issue #20](https://github.com/Hi-Yincan/LifeOS/issues/20) 跟踪，待明确恢复后再推进。** 未向第三方发送消息；没有将待确认身份冒充站长账号。

## 这是什么应用

当前 daedalOS Messenger 是 Nostr 私信客户端，与 Meta/Facebook Messenger、微信和本站 admin 单密钥不是同一身份体系。此固定版本支持 NIP-17/NIP-44 加密私信，并为旧客户端保留 NIP-04 兼容。公钥标识联系人，私钥或兼容签名扩展控制身份；显示名称不能单独确定收件人。

`getSigner()` 在没有可用本地密钥或扩展身份时自动生成身份，将本地私钥保存于当前 origin 的 localStorage。因此访客不必注册本站账号，但同一访客更换浏览器、清除站点数据后，若未备份/导入原身份，就不会自动成为同一联系人。不要将站长私钥写入仓库、公共配置或聊天。

## 所有访客能否即时联系站长

可将站长的公开公钥预置到联系人列表，让能连接中继的访客直接发送。站长必须实际控制对应身份，并使用同一身份打开本站 Messenger 或兼容客户端收取消息；加入一个名称不会自动建立可收信账号。管理员登录不会切换 Nostr 身份。

这不是已验收的在线客服：

- 消息通过 WebSocket 中继收发；双方在线且中继路由匹配、网络可达时可近实时通信。中继的存储与访问策略影响离线取回，国内外可用性尚未实测。
- 代码中的发送成功表示至少一个中继接受事件，不是收件人已读或已收到的回执。
- 新联系人消息进入 Message requests；在回复前不会触发普通聊天的声音/未读计数。站长需要查看请求列表。
- 当前客户端仅在应用运行期间订阅消息、更新窗口标题并播放提示音；未发现后台推送实现，不能承诺关闭网页后继续即时提醒。
- 默认历史查询为近一周，可通过现有时间范围控件查询更早消息；不能把暂未显示等同消息不存在。

当前实现优先读取收件人的 kind 10050 私信中继配置，缺失时回退到五个预设中继。现行官方 NIP-17 对没有 kind 10050 的收件人要求更严格：应视为尚未准备接收。正式启用站长联系前，应明确发布站长私信中继配置，并验证兼容客户端的收发与离线取回，不把现有回退当作可靠交付保障。

待负责人提供 **公开 npub / 64 位十六进制公钥 / 可解析的 NIP-05 地址**，或确认尚无 Nostr 身份。不得以姓名搜索结果猜测身份，也不预填假的公钥。

收到公钥后：将站长公钥加入本站预置联系人，将本机展示名固定为 Yincan Huang 并复用头像，验证不覆盖远端签名身份资料；再确认中继与接收端。可将 `yincan@hyc.ac` 作为后续 NIP-05 映射，使用 `/.well-known/nostr.json`，这不是邮箱，也不需要为此更换 DNS；仍须在实际站点发布后才能对外解析。映射不会替代私信中继配置。
