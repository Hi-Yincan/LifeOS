# 展示型个人 OS 选型验证

关联：GitHub Issue #1 / R12。日期：2026-10-16。

本目录为隔离的技术实验，不是生产实现或已批准的最终技术栈。使用明确标注的合成博客与衣柜数据，不导入作者的真实健康、照片或私有资料。

## 研究问题

能否复用现有 OS 框架，仅注册博客与衣柜两个内容 App，并把 visitor/admin 权限交给统一内容服务，而不引入通用云电脑的全部功能？

## 实验边界

- 对现有 Puter 实例做浏览器现状走查和源码定点核验，记录可扩展点与未验证项。
- 用发布版 `@prozilla-os/core` 组合两项内容 App，构建生产资源并实际运行。
- 内容服务是本实验的最小测试夹具，使用本地文件存储、临时会话和测试身份。它验证权限边界和内容生命周期，不证明生产认证、CMS、备份、高并发或完整安全审计已完成。
- 服务仅绑定 127.0.0.1，启动需要显式提供实验登录口令；不复用 Puter 管理员凭证。

## 验收场景

| ID | 场景 | 预期 |
| --- | --- | --- |
| V01 | 未登录打开首页 | 只出现博客和衣柜的自定义应用入口；能读公开内容 |
| V02 | 管理员登录并保存新衣物草稿 | 管理视图可见，独立访客会话和公开详情不可见 |
| V03 | 发布与下架 | 发布后访客可读；下架后公开列表、详情和图片均不再返回内容 |
| V04 | 匿名或普通登录用户直接写 API、伪造角色 | 服务端拒绝；身份不从请求中的 role 字段推断 |
| V05 | 私有图片、私有备注、跨站写入 | 访客无法读取私有资源；公开响应不包含管理字段；外源写入被拒绝 |
| V06 | 注销及服务重启 | 注销令原会话失效；已保存的内容在服务重启后仍存在 |
| V07 | 桌面与 390px 界面 | 可打开、阅读、管理、返回；手机不用拖拽窗口 |
| V08 | 内容链接刷新与浏览器返回 | 直接打开文章/衣物链接可定位相同内容；未知 URL 返回 404 |
| V09 | 可复现性与资源 | 锁定依赖，构建成功，记录原始/压缩资源；不与开发态 Puter 作不公平速度排名 |

## 待决事项

最终 OS 框架、生产认证与内容服务、公开图片缓存和撤回策略、真实内容迁移、设计风格及部署环境不在此实验中冻结。
