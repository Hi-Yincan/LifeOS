# ADR：单仓产品源码与上游同步

状态：负责人于 2026-10-17 确认推进；实施 Issue #21，职责来源 #10 / #11。

采用一个正式产品仓库，导入并保留 daedalOS 完整 Git 历史。当前不创建独立 fork/模板仓库，不使用 submodule。自有 App 与配置直接纳入产品源码，原型 overlay 冻结为研究记录。前端与内容 API 可以同仓维护、独立部署；本次仅迁移本地开发 API，不把它认定为生产后端。

上游目录尽量保持原布局，变更在应用、品牌、系统适配、构建/测试四类中记录。固定 SHA、锁文件和运行版本；常规升级使用独立 Issue/分支/PR，保留合并历史，检查重叠修改并完成回归与回退。普通构建不下载或修改上游 checkout。

独立底座/模板仓库的触发条件：出现第二个真实复用站点、通用配置/应用接入接口已验证、底座有独立发布和兼容测试收益。submodule 仅可在该时评估为源码版本锁定方式，不能当作插件接口或数据备份。

验收：完整 ancestry、干净克隆构建、原生注册保留、产品和开发服务回归、两个真实上游 SHA 的升级及代码/产物回退证据。主分支合并、生产发布与数据迁移继续走各自评审。
