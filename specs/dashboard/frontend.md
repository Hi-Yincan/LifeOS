# 综合看板前端设计与演示实现

2026-10-18 · 当前实施范围。用户在开始开发时明确：**本次只设计前端，允许模拟数据；需要后端服务先记录、先别开发；无法确定的内容先跳过，最后集中询问。** 最新决定为：**日常健康同时展示全部四项指标；LifeOS 取消管理员功能，所有人读取相同内容，站长从独立信息源系统维护内容。** 本文按最新决定维护，优先于此前 PRD 和历史验收中的 App 内编辑、公开范围、延迟及访客预览要求。真实来源接入仍属后续阶段，不因前端完成而关闭整组业务 Issue。

同日 UI 迭代中，用户已确认按展示的草案直接修改现有前端。布局采用左侧竖向模块与个人子分类、右侧紧凑内容和详情；现有业务含义与模拟数据继续保留。此前未定的数据源、公开规则与后端问题留待后续确认，本轮不重新询问。

服务视图采用逐行健康状态展示：服务名与当前状态、可用率、最近 90 个完整 UTC 日状态条。只参考成熟状态页的信息结构，继续使用 LifeOS 深灰表面和自有合成历史。综合看板不提供单独的“清除筛选”按钮，筛选恢复通过原有搜索、全部选项和分类切换完成。

## 本轮交付

在现有 daedalOS 内增加一个单实例 `Dashboard` 应用，包含总览、个人、会员、服务、服务器五个视图。使用真实 React 组件、原生窗口/工具栏/状态栏/主题/滚动条与中英双语，完成可操作的筛选、详情、趋势切换和跨模块阅读。各模块使用同一套确定性的合成数据，全部示例直接可读；前端状态仅维护当前导航、筛选和展开内容。

应用状态区持续显示“示例数据”、固定示例时间和“只读浏览”；“示例说明”展开后明确所有记录均为虚构、展示全部示例。所有账号、会员金额、服务器、活动、健康和位置均为虚构演示记录；不能使用作者真实资料，也不把这些记录加入 `server/content/seed.json` 或作品集公开内容。示例时钟固定并可读，用于让临期、历史和陈旧场景可复现，不冒充当前真实监控。

所有人在 LifeOS 中查看相同内容，LifeOS 没有站长特权或编辑模式。访客/站长预览、逐项公开范围、公开/私有标记、延迟/历史窗口设置、新增/编辑/保存、付款确认、续费修改与重置示例的入口及内部实现均已删除。当前全量展示仅适用于虚构样本；真实来源由独立信息源系统提供统一展示数据，旧草稿和私有信息不自动公开。源侧管理、真实连接器与认证只出具 [可行性报告](../architecture/source-managed-content.md)，本轮不实现。

会员既有的权益状态、续费计划与已确认模拟付款历史继续展示，但不提供修改或执行入口。服务商入口不产生付款或取消操作；本轮不执行真实付款或第三方账户操作。

会员、服务和服务器在同一模块的列表与详情之间往返时保留搜索、分类、状态与排序。正常关闭/重开、浏览器前进/后退和刷新无需处理编辑草稿。筛选无结果时可清空原搜索框、选择“全部”或再次点击已选分类；包括个人检查类型在内，综合看板不单独提供“清除筛选”按钮。没有数据、未配置、陈旧与错误使用不同文字。入口、图例、状态与数据表可用键盘访问，不仅依靠颜色。

### 四项日常健康

步数、心率、睡眠时长、体重始终同时展示为四张有独立标题的记录卡，不再通过指标选择器隐藏其他指标。宽窗口自然排成两列；窄窗口排成一列，依据应用可用宽度变化。每卡包含当前值、单位、记录时间与新鲜度、趋势和可展开的样本表/记录说明/来源，共用一个时间范围选择器。

“最近一天 / 最近一周 / 全部”同步更新四项趋势，卡片数量与当前值不变。缺测点保留断线，不补零。体重示例没有记录，仍保留完整卡片、单位和“无样本不等于零”的说明；不得因为没有数据隐藏指标。旧心率实体深链继续进入日常健康，并同时显示四项。示例当前值为 6,420 步、72 bpm、7.4 小时和 — kg；默认周范围样本数分别为 12、24、7、0。

全部虚构活动、日程、路线和检查记录可读，不按历史公开标记、延迟或历史窗口筛掉样本。这不表示真实个人健康或位置数据已公开。

### 服务健康历史

每行展示名称/当前状态、右侧 90 日可用率和覆盖率、下方 90 日状态条。日期按固定示例时钟之前的完整 UTC 日计算，不包含当日尚未完成的窗口；当前示例为 2026-07-20 至 2026-10-17。健康历史与响应延迟历史分别保存，列表与详情使用同一统计口径。

可用率为正常检查数除以已观测检查数，异常与故障纳入分母，缺测不纳入；覆盖率为已观测除以预期检查。完全没有观测时可用率显示“—”，不会显示为 0% 或 100%。预期样本全部正常为绿色，有异常为黄色，有故障为红色；无样本或只有部分正常样本时为灰色。部分缺测日若已观测到异常/故障，仍保留对应严重度，并在详情说明覆盖。

每条历史只有一个键盘停靠点，支持方向键、Home/End 选择日期，Escape 隐藏日详情；悬停或触摸也可以选择日期。日详情提供 UTC 日期、状态、正常/已观测检查和已观测/预期覆盖，不只依赖颜色。无监测、来源陈旧和当前 pending 状态仍分别说明，历史百分比不冒充当前实时状态或 SLA。

## 原生接入与视觉

- 进程目录注册单实例Dashboard；开始菜单、App Store与单个桌面快捷方式打开同一窗口。桌面布局交给原生机制，访问网站不自动打开看板。
- 商店归应用软件，提供中文/英文说明；图标用小型原创SVG，与现有原生图标风格接近，不复制竞品商标。
- 左侧始终竖向排列五个模块；进入个人后，在同一侧栏展开活动/日程、位置/轨迹、日常健康和检查记录。右侧展示当前模块列表和详情。窄窗口压缩侧栏文字与间距，保持完整可访问名称；侧栏和内容可分别滚动。
- 顶部原生位置栏保留返回与当前位置；状态区集中示例时间、只读状态和说明。主体使用紧凑中性表面、方形边界和统一选中/焦点态，不添加独立品牌大标题、第二套皮肤或移动端外壳。
- 总览采用紧凑摘要、当前/下一日程和待处理事项，完整费用口径、来源时间及超过首批的事项可展开查看。会员使用费用摘要与可扫描列表，窄窗口省略的费用/日期列仍可在详情查看；服务采用逐行健康状态条；服务器使用资源比较表，必要时在表格区域内横向滚动。
- 内容仅随窗口宽度自然排列和滚动；不根据设备类型改变OS导航或强制全屏。图表同时给出可访问文字/表格，不能用假数据连续曲线掩盖缺测。
- 独立查询参数定位Dashboard模块/实体，不占用Portfolio的view/project参数；正常前进/后退、刷新和原生窗口恢复均需要测试。

## 前端结构和并行所有者

`model.ts`、`fixtures.ts` 与共享控件定义 `DashboardViewProps`、模拟时钟、数据工厂和导航；五个视图在独立目录内维护。当前应用读取全部样本，已删除写入回调、角色、政策投影、表单与编辑专用模型。读取金额、权益、计划、趋势、缺测和来源时间的算法保留。所有并行修改都在指定 worktree 和 owned paths 内；共享文件只有一个写入负责人。

只使用当前依赖和锁文件，不增加图表/状态管理库来替代小型明确实现。没有真实外部数据时使用类型化fixture；生产接口、认证、抓取和同步都不创建。纯计算有重要边界时做必要单测；主要证据来自实际浏览器交互，不为静态布局逐行写测试。

## 本轮验收

1. 公开静态构建中能打开五个视图，示例标识、固定时间、只读状态和全量虚构内容说明可见，无 Dashboard 网络数据请求或业务持久化。
2. 菜单、商店、桌面、深链接与重复打开使用同一实例；Portfolio及默认桌面回归通过。
3. 五视图的搜索/筛选、详情、趋势/时间范围、历史与跨模块入口实际可操作；六个会员、六个服务、四个服务器和全部个人样本可读。四张健康卡持续存在，日/周范围同步更新，体重空状态和心率缺测保留。确认所有视图无编辑、付款、续费、重置或可见性控件。
4. 中文与英文、键盘、桌面/1024×768/390×844视口及受影响窗口缩放检查；另在桌面宽视口中实际拖动原生窗口至约 520px 宽，验证布局依据应用宽度改变、竖向导航和详情仍可操作。仿真与真机明确区分。
5. 所有指标口径与模拟状态一致，无混币、缺失置0、原始时间冒充新测量或真实授权等误导。移除的历史编辑/隐私用例不计作本轮通过项；当前证据见 [管理员功能移除验收](../development/validation/lifeos-admin-removal.md)，此前 UI 记录见 [全部健康与只读浏览验收](../development/validation/dashboard-all-health.md)。
6. 使用Node22.23.3/Yarn1.22.22和当前依赖，在隔离工作树完成适用构建、lint、单元测试和Playwright；真实后端、设备与生产验收保持未执行。
