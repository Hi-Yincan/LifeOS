# 资源就绪启动界面

关联 Issue：[#52](https://github.com/Hi-Yincan/LifeOS/issues/52)。

## 行为与范围

首次访问与刷新均先显示 OS 启动界面：复用开始菜单的 π 标识、系统字体、黑色背景与主题高亮，站点名读取 `lifeos.json`。五个小点仅表示正在工作，不显示模拟百分比。标识、文字、样式与控制脚本直接输出到 HTML，不下载启动图片、字体、视频或动画库。应用样式先以非阻塞方式下载，下载完成后启用；桌面在背后完成初始化。

只有会话恢复、应用样式、桌面目录与快捷方式图标及字体、任务栏时钟首帧、壁纸就绪后才开放桌面。默认银河通过渲染器实际画出首帧通知主线程，图片背景在解码后就绪，视频等待首帧数据；恢复的其他动态背景等待其初始化/首帧通知。应用包、游戏资源、内容服务和未打开窗口不属于开机前置资源，继续按需加载。显式应用深链接沿用原有行为。

资源就绪后的下一帧直接隐藏界面并解除 `inert` 与可访问性隔离。若深链接窗口已经在背后挂载，解除隔离后重新激活该窗口，继续使用原生焦点逻辑维护窗口层叠顺序。没有最短展示时长、强制淡出、模拟进度或等待一轮动画。缓存命中时允许启动界面极短出现。启动中的系统快捷键不能穿透到尚未就绪的桌面。

脚本/样式下载失败显示错误与「重新加载」；20 秒后仍未完成则提示网络可能较慢并提供同一重试入口。此计时器不放行桌面、不取消仍在进行的资源加载。浏览器语言与既有本机语言偏好决定启动文案；存储不可用时继续使用浏览器语言。减少动态效果偏好下小点静止。禁用 JavaScript 时显示原因。404 页面不挂载启动门禁。

头像图标、favicon 与旧图标入口的下载体积优化见[首屏头像资源优化](startup-assets.md)；继续等待实际显示资源解码与壁纸首帧，不增加或绕过启动阶段。

## 验证

2026-10-21 使用 Node 22.23.3、Yarn 1.22.22 和实际 Chromium 验证。`e2e/boot.spec.ts` 共 11 项，覆盖脚本与样式延迟、桌面图标和壁纸 worker 延迟、失败后的键盘重试、长时间等待、中文与减少动态效果、三个视口、404、非 OffscreenCanvas 路径以及深链接窗口的焦点恢复。

视觉复核使用 1280 × 720、768 × 1024、390 × 844 的真实浏览器截图。视口模拟不替代手机或 iPad 真机验收；本轮没有验证 Safari / Firefox、不同地区的真实网络或生产发布。原生 App、桌面拖放、看板、作品集、商店、设置和 Messenger 的既有产品测试均保留并通过。

验收曾发现启动中的 `inert` 阻止深链接窗口初始聚焦，使窗口没有进入原生层叠顺序。已在解除隔离时恢复前台窗口焦点，新增回归测试先复现失败、修复后通过；未更改窗口管理器的层叠规则。
