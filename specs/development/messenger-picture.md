# Messenger 本地头像编辑

2026-10-18，关联 Issue #20。负责人本次明确要求将头像编辑改为本地选图与圆形裁剪预览；站长联系人仍需负责人提供其控制的公开公钥，本次不创建或发布站长身份。

## 行为与范围

- 点击个人头像菜单中的「修改头像 / Edit Picture」进入编辑界面，不再要求手动输入 Picture URL。
- 选择不超过 10 MB 的 JPG、PNG 或 WebP 图片，默认居中裁剪；支持缩放、水平与垂直位置调整、圆形预览。拒绝无法解码或超过 4000 万像素的图片。
- 预览与位置调整在浏览器内完成，只有点击保存才签名并发布资料。取消、Escape 或返回按钮退出编辑；取消与保存完成后焦点返回个人头像按钮。
- 复用 Messenger 窗口与 OS 语言选择。编辑时使用 File Explorer 原生导航栏、返回图标、位置栏、状态栏及 PersonalOS 共用表单样式；返回后恢复聊天资料栏。文件名栏与「浏览」按钮选择本地图片，裁剪区使用分组边框、圆形预览、带数值的紧凑滑块，保存与取消固定在底部。
- 内容在窄窗口中自然换行与滚动，宽窗口中的表单限制为 560px；保留原生窗口最大化、还原和最小化机制。
- 保存前读取现有资料并合并 picture 字段，保留其他资料字段。至少一个中继接受事件才更新本机资料并退出编辑；全部失败时显示错误并保留裁剪内容，可重试。
- 名称及背景图继续使用原有编辑入口，共用资料保存函数；保存失败现在明确报告。

## 图片保存方式与边界

当前生产为静态站点，没有面向访客的图片上传后端。本次沿用现有 `dataToProfile` 对 `data:` 图片地址的支持，将裁剪后的 192×192 JPEG 编码为 data URL，写入 Nostr kind 0 资料的 picture 字段。编码结果不超过 16 KiB，按需降低 JPEG 质量，不能满足上限时拒绝保存。原始文件不发送到中继，也不发送到额外图床。

存储图片保持正方形，界面使用圆形遮罩；透明背景在导出 JPEG 时填充白色。不同于临时 blob URL，此值包含图片数据，支持该格式的接收方可独立显示。其他 Nostr 客户端及各公共中继的兼容性未验证，不能据此宣称通用图床支持。

实现依据：当前仓库 `components/apps/Messenger/functions.ts` 的 `VALID_PICTURE_PROTOCOLS` 与 `dataToProfile`，以及 `NostrContext.tsx` 的资料发布接口。
